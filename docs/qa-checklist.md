## 기준

- **QA 기준 브랜치: `bum8844_clone`** (네 명의 작업을 합친 통합 브랜치)
- **시작 시점의 기준 커밋: `b23bc81`**
- `main`에는 직접 푸시하지 않습니다. 모든 항목을 확인한 뒤에 `bum8844_clone`을 `main`으로 한 번에 PR합니다.

## 시작하기 전에

### 1. 브랜치 받기

```bash
git fetch origin
git switch bum8844_clone
git pull
```

이미 `bum8844_clone`이 로컬에 있으면 `git switch bum8844_clone`과 `git pull`만 하면 됩니다. 커밋하지 않은 변경이 있으면 먼저 커밋하거나 `git stash`로 치워 두세요.

### 2. 옛 데이터로 확인하려면 (선택, 권장)

모델이 바뀌었기 때문에, **업데이트 전에 저장된 글이 새 버전에서도 열리는지**를 확인해야 합니다.

1. 시뮬레이터에 옛 버전으로 글을 몇 개 저장합니다. (옛 버전: `git switch --detach 9900302`로 이동해서 실행. 끝나면 `git switch bum8844_clone`으로 돌아옵니다.)
2. 앱을 지우지 않고 `bum8844_clone` 최신으로 다시 실행합니다.
3. 목록과 상세에서 그 글들이 정상으로 보이는지 확인합니다.

시뮬레이터를 초기화(`Erase All Content and Settings`)하면 이 확인을 할 수 없으니, 확인이 끝난 뒤에 초기화하세요.

## 수정할 때 지킬 규칙

- 이슈는 **해당 영역 담당자가 고칩니다.** 다른 영역의 파일을 고쳐야 하면 담당자에게 먼저 알립니다.
- 수정하기 전에 `git pull`로 최신을 받고, 수정한 뒤 `bum8844_clone`에 푸시합니다.
- 커밋 메시지는 `<type>(<scope>): <subject>` 형식(영어, 명령형)이고, 본문은 한글 목록으로 적습니다.
- 같은 파일을 둘이 동시에 고치지 않도록 팀 채팅에 "어느 파일을 고치는 중"인지 남겨 주세요.
- 충돌이 나면 임의로 한쪽을 고르지 말고 채팅에 먼저 알립니다.
- `main`에는 직접 푸시하지 않습니다.
