# 카드 높이 통일·분류없음/태그 없음 통계 QA

2026-11-20. 팀 `upstream/work/yeongyu` 공유용 문서입니다.

## 변경 내용

- 태그 없는 카드도 태그 한 줄 공간을 확보합니다. `@ScaledMetric`을 사용해 큰 글씨에서도 태그가 있는 카드와 같은 줄 높이로 늘어납니다.
- 기존 태그 한 줄 말줄임은 유지합니다. 카드 전체를 고정 높이로 강제하지 않으므로 제목·날짜 등 다른 조건의 차이까지 없애는 것은 아닙니다.
- 통계에 **분류없음 / 태그 없음** 건수 행을 추가했습니다. 행을 누르면 선택한 작성 주·월에 해당하는 글만 조회하고 상세로 이동할 수 있습니다.
- 두 조건에 모두 해당하는 글은 각 항목에 포함하지만 전체 회고 건수에서는 한 번만 셉니다.
- 0건도 표시하며 눌렀을 때 해당 기간에 글이 없다는 안내를 보여 줍니다. 조회 목록 위에 기간을 표시합니다.
- 태그 유무 판정은 목록 필터·통계가 같은 `JournalTag` 함수를 사용합니다. 공백이나 `#`만 있는 값은 태그 없음으로 취급하고 가짜 태그를 저장하지 않습니다.

## 게시 범위

기준 브랜치의 기존 커밋 `0c4822d` 위에 아래 코드 6개 파일만 추가/수정합니다.

| 파일 | 역할 |
| --- | --- |
| JournalTag.swift | 순수 문자열 태그 정규화·태그 없음 판정 |
| JournalDatabase+Classification.swift | 기존 태그 API와 필터를 공통 판정에 연결 |
| JournalCardView.swift | 글자 크기에 대응하는 공통 태그 줄 높이 |
| ReflectionStatistics.swift | 분류없음·태그 없음 집계 |
| ReflectionStatisticsCharts.swift | 두 건수 행과 조회 버튼 |
| ReflectionStatisticsView.swift | 같은 기간의 원본 글 목록·상세 연결 |

SDK 주석·프로젝트 설정·AI·정렬 옵션은 변경하지 않습니다. 다른 팀원의 목록 날짜 구간 묶음, 카드 날짜/중요도 배치 등의 작업도 이번 커밋에 섞지 않습니다. DB 스키마 변경은 없습니다.

## 카드 높이 실측

Xcode 27.2, iPhone 18 Pro / iOS 27.2. 같은 제목·분류·날짜·중요도의 실제 JournalCardView를 UIHostingController에서 폭 353pt로 비교했습니다. 태그 유무만 다르게 두었습니다.

| 글자 크기 | 태그 없음 | 태그 있음 | 차이 |
| --- | ---: | ---: | ---: |
| large | 130pt | 130pt | 0pt |
| xxLarge | 144pt | 144pt | 0pt |
| accessibility3 | 약 205.67pt | 약 205.67pt | 0pt |

위 수치는 통합 작업본의 카드 배치에서 측정한 값입니다. 이번 게시용 브랜치에는 다른 팀원의 배치를 새로 넣지 않으므로 절대 높이는 달라질 수 있지만, 태그 줄 높이를 맞추는 변경 자체는 동일합니다.

처음 시도한 빈 Text의 줄 예약 방식은 접근성 글씨에서 높이 차이가 있어 폐기했습니다. 최종 공통 줄 높이 방식으로 세 크기에서 차이가 없어졌습니다.

## 빌드·로직 검사

- 통합 수정본: 신규 집계 10건 + 기존 통계 14건 + 분류·날짜·태그 필터 16건 = **40건 통과**.
- 게시용 코드만 적용한 상태: 신규 집계 10건 + 기존 통계 14건 + 분류·날짜·필터 15건 = **39건 통과**. 제외된 1건은 이번 커밋에 넣지 않는 다른 팀원의 목록 날짜 함수 검사입니다.
- 게시용 Release 빌드 성공. AppIntents 메타데이터 추출 생략 경고 1건, 제품 소스 컴파일 오류 없음.
- 새 태그 함수는 문자열 계산만 하므로 `nonisolated`를 명시해 MainActor 관련 경고를 해소했습니다.
- `git diff --check` 통과.

사용자 조작·높이 측정은 통합 로컬 작업본에서 진행했고, 실제 게시 범위는 `0c4822d` 위에 필요한 부분만 적용해 별도로 빌드·검사했습니다. 일부 날짜·분류 함수 검사는 DB I/O를 분리한 경량 값 타입을 사용합니다.
