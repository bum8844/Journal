# 통계·설정 구현과 팀 통합 계획

## 현재 D 작업

- iPhone 하단 `TabView`는 회고 · 통계 · 설정 순서다. 회고 탭은 목록 화면 연결 전까지 임시 화면을 표시한다.
- 통계 탭은 기본으로 이번 달을 연다. 이전·다음 달로 이동하며 월별 회고 건수와 태그별 회고 건수를 표시한다. 같은 회고에 동일 태그가 반복되면 한 번 센다.
- 설정 탭은 시스템 · 라이트 · 다크를 선택한다. `JournalApp`이 `@AppStorage("appTheme")`로 값을 저장하고 앱 전체에 적용한다.
- 월별 통계는 `JournalDatabase`에 저장된 회고를 사용한다. 앱 내 프리뷰는 인메모리 컨테이너를 사용한다. README의 주간 통계도 최종 과제 범위에 포함되므로 주간 화면은 후속 작업으로 둔다.

## 연결 순서

1. **공통 작업** — 현재 팀 코드의 `JournalDatabase` 모델과 `JournalApp`에 연결된 SwiftData 컨테이너를 사용한다. `category`는 모델에 포함하고, `createdAt`과 `tags`는 README의 타입을 사용한다. `JournalApp`에 컨테이너를 연결할 때 기존 테마 적용도 함께 둔다.
2. **A·B·C** — B의 목록 화면을 `ContentView`의 첫 번째 탭에 연결한다. 목록 화면 안에 이미 `NavigationStack`이 있다면 탭에서 중복으로 감싸지 않는다. 작성·편집은 A, 목록의 태그 필터는 C와 연결한다.
3. **D** — `ContentView`는 통계 탭에서 `MonthlyStatisticsView()`를 엽니다. 통계 화면의 `@Query`가 `JournalDatabase`를 읽고 작성일과 태그를 `MonthlyStatistics`에 넘겨 선택한 달을 집계합니다.

4. **팀 검증** — 서로 다른 달의 회고를 작성해 월별 건수와 태그 빈도를 확인한다. 태그 수정과 스와이프 삭제가 집계에 반영되는지 확인한다. 하단 설정 탭에서 테마를 바꾸고 다른 탭에도 적용되는지, 앱을 재실행해도 유지되는지 확인한다.
