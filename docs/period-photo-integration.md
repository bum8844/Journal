# 시안 B 기간·사진 입력 연동 안내

이 문서는 기간·사진 입력 뷰를 작성·편집, 목록·상세, 공통 모델·필터에 연결할 때 참고할 메모입니다. 저장 필드와 기본값은 [공통 모델 공지](model-fields-notice.md)를 기준으로 합니다.

## 작성·편집

- 새 회고는 하루 모드와 사진 없음으로 시작합니다. 편집에서는 저장된 `isPeriod`, `startDate`, `endDate`, `photoData`로 초기화합니다. 기존 글의 `startDate`가 비어 있으면 화면에 `createdAt`을 보여줍니다.
- `JournalPeriodPicker(value: $period)`와 `JournalPhotoPicker(photoData: $photoData)`를 작성폼에 연결합니다. 사진을 제거하면 `photoData`가 `nil`이 됩니다.
- 기존 제목·형식별 내용 검사에 `period.isValid`를 추가합니다. 저장 버튼과 실제 저장 처리에서 같은 조건을 확인합니다. 자유 형식은 `content`, KPT·4L은 `answers`에 입력한 내용을 기준으로 검사합니다.
- 저장할 때 `isPeriod`와 기간 날짜를 맞춰 씁니다. 기간 종료일은 `period.savedEndDate`로 받고, 하루로 바꾸면 기존 종료일이 지워집니다. 하루의 선택일을 `startDate`에 저장할지는 아래 확인 항목을 따릅니다. 사진은 바인딩으로 받은 `Data?`를 저장합니다.

## 목록·상세

- 목록은 `isPeriod`로 종류를 구분합니다. 기간 회고에 시작·종료일이 모두 있으면 상세에 날짜 범위를 표시합니다. 형식별 답변은 `format`과 `answers`에서, 사진은 `photoData`에서 읽습니다.
- 기존 글의 날짜는 `createdAt`으로 표시하고, 사진이 없으면 사진 영역을 생략합니다. KPT·4L 답변을 검색할 수 있게 할지는 목록 담당과 팀에서 결정합니다.
- 상세에서 편집으로 들어가 기간을 변경하고 사진을 교체·제거한 뒤, 목록과 상세가 저장된 값을 다시 표시하는지 확인합니다.

## 공통 모델·필터

- 현재 모델에 `format`, `answers`, `isPeriod`, `startDate`, `endDate`, `photoData`가 있으므로 위 기능에 추가 저장 필드는 현재 필요하지 않습니다. 사진 필드에는 `@Attribute(.externalStorage)`가 이미 적용돼 있습니다.
- 기존 회고는 자유 형식, 하루, 사진 없음으로 처리합니다. 기존 글과 신규 기간 회고 모두 같은 카테고리·태그 필터로 찾을 수 있는지 확인합니다.
- 작성·편집에서 `isPeriod`와 종료일의 조합이 일관되게 저장되는지 확인합니다. 기간 회고는 시작·종료일이 있고, 하루 회고는 종료일이 비어 있습니다.

## 팀에서 확인할 날짜 규칙

- **하루 선택일 저장** — `startDate`를 하루 회고의 선택일에도 사용할지 공통 모델 담당과 합의합니다.
- **목록·상세와 통계** — 현재 목록 정렬과 주·월간 집계의 기준은 `createdAt`입니다. 회고 대상 날짜로 바꾸기로 하면 목록·상세 표시와 정렬, 통계 건수·태그·일별 차트를 같은 기준으로 맞춥니다. 제안은 하루는 선택일, 기간은 시작일에 한 건, 날짜가 없는 기존 글은 `createdAt`입니다.

**통합 확인** — 기존 글 열기 → 사진이 있는 기간 회고 작성 → 앱 재실행 → 기간 변경 및 사진 교체 → 하루로 전환하고 사진 제거 → 상세·필터·통계 확인.
